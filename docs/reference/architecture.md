# Architecture

## High-level shape

```text
Browser → Caddy (HTTPS) → FastAPI (uvicorn)
                             ├── REST API
                             ├── WebSocket
                             └── Static frontend assets
```

## Backend

Key backend files:

- `backend/server.py` — FastAPI app, SSE/REST routing, static file serving
- `backend/agent/agents.py` — agent configuration, model fallback, system prompts
- `backend/agent/tools.py` — bash, file, search, and web tools
- `backend/agent/context.py` — injects project context such as `AGENTS.md` and directory tree
- `backend/agent/context_manager.py` — multi-layer context window management pipeline
- `backend/agent/compact.py` — Layer 3 full compaction (summarizes all old messages)
- `backend/agent/token_estimate.py` — centralized token estimation utilities
- `backend/data/storage.py` — flat-file persistence for projects and conversations
- `backend/data/models.py` — Pydantic models for REST API
- `backend/data/protocol.py` — SSE event models
- `backend/runtime/runner.py` — agent execution loop, tool approval, history management
- `backend/runtime/sse.py` — SSE stream handler, context management trigger

## Frontend

Key frontend files:

- `frontend/src/main.tsx` — app entry, routing, auth gate
- `frontend/src/api.ts` — REST and WebSocket client
- `frontend/src/views/Chat.tsx` — main chat UI
- `frontend/src/views/ProjectList.tsx` — project list page
- `frontend/src/views/ConvoList.tsx` — conversation list page
- `frontend/src/components/FilePanel.tsx` — side panel for viewing and editing files
- `frontend/src/components/CodeMirrorEditor.tsx` — full editor, lazy-loaded
- `frontend/src/components/FileFinder.tsx` — file finder modal

## Persistence model

Remote Lab uses JSON files on disk instead of a database.

```text
data/
  projects.json
  agents/_global.json
  agents/{project_id}.json
  conversations/{id}.meta.json
  conversations/{id}.jsonl
  conversations/{id}.agent.{agent_id}.json
```

This keeps the system easy to inspect, back up, and modify.

## Execution model

A key design choice is that agent runs are decoupled from the browser connection.

The backend runs agent work as an async task. If the browser disconnects, the task can keep running. When the client reconnects, it receives the persisted history and any new streamed events.

## Context management

Context is managed progressively through a three-layer pipeline (`backend/agent/context_manager.py`) that runs before each agent turn. Each layer is more aggressive than the last, and only activates when the previous layer wasn't enough.

**Layer 1 — Tool result trimming (>=50% of budget).** Large tool results in older turns are replaced with structured summaries. No LLM call — summaries are generated by extracting metadata from the content itself. For example, a 100KB `read_file` result from 5 turns ago becomes `[Previously read backend/server.py: 450 lines, Python. Defines: class Server, handle_request, main]`. Results under 1KB are kept as-is. Results between 1-5KB are truncated to first/last 500 chars. Results over 5KB get full structured summaries. Recent turns (last 3) are never trimmed. If the same file was read in both an old and recent turn, the old read is always trimmed (deduplication).

**Layer 2 — Chunked turn summarization (>=70% of budget).** Old turns are grouped into chunks of ~5 and each chunk is summarized by a lightweight LLM call. This preserves temporal structure better than a single monolithic summary — the history becomes a series of chunk summaries followed by the recent turns in full.

**Layer 3 — Full compaction (>=85% of budget).** All old messages are summarized into a single block, keeping only the last 3 turns intact. This is the most aggressive option and the original compaction behavior. Also available manually via `/compact`.

Real token counts come from the model API (`usage.request_tokens`) after each turn and are used as input to the pipeline on the next turn. Between layers within a single pipeline run, token counts are estimated using per-content-type heuristics from `backend/agent/token_estimate.py`. Each model has a budget calculated as `min(soft_limit, 80% of context_limit)` — thresholds are fractions of this budget.

## Project scoping

Each project points to a real directory on disk. Agent tools run relative to that directory and are sandboxed to it.
